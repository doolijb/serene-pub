### Scripts (worker w1; sandbox JS)

**One lookup.** All of these now use `stateKeyOf(ref, byId)`:
- `shared/reckoning.ts` (the Story preamble)
- `dungeon-crawler/preamble.ts`
- `dungeon-crawler/roundScript.ts` (it has its own copy, because it does not open on the preamble)

The lookup returns the `state.cast.byId` key whose entry's `ref` equals the ref. It falls back to today's card-form key ⏳ only when the entry under that key has no `ref` of its own. Card ids and member ids share one range, so the old key is never trusted while the entry carries a ref. Every caller passes `byId`. `state.configs` is keyed like `byId` (`resolve.ts` `configsFor`), so the same key serves both.
