## The function
`state/storyTime.ts`: ★ `loreWriteDateOf(db, sessionId)` returns ★ `LoreWriteDate`, one of:
- `{kind:'dated', date: StoryDate, hangsOn: number|null}`: `date` never null; `hangsOn` from `writeDatingAt`, may be null.
- `{kind:'timeless'}`: the lorebook keeps no timeline.
- `{kind:'undatable'}`: a timeline and no date at all.

Backstop: ★ `undatedLoreWriteRefusal(db, sessionId, date)` and ★ `UNDATED_LORE_WRITE_SENTENCE`. It reads the truth through an unexported function, so a test that mocks `loreWriteDateOf` still hits the real check.

## Write kinds (before → after)
| Write | Before | After |
|---|---|---|
| `create-lore-entry`, an entry that begins when made (Item) | date from the clock only; with dated history and no clock stored Perpetual silently | the story's day (the newest history day when there is no clock). Perpetual types (World lore, Place) stay Perpetual. Backstop before the insert |
| `create-lore-entry`, history | story now, else refused | unchanged (through the function) |
| `update-lore-entry`, attached lorebook entry | dated version only with a clock, else in place | dated version whenever `dated`; in place only when `timeless` or `undatable`. Backstop before an in-place write |
| held change | held with the clock's date, else undated | held with the story's day. Backstop |
| `update-lore-entry`, an entry in the session notes | in place | verified unchanged |
| pipeline re-dating an attached lorebook's history entry (dated history, no clock) | moved in place | refused "*keeps its date in the lorebook*", as it already was with a clock ★ |
| `update-cast-member` (`storyWrite`; also the Dungeon Crawler's cairns) | attached lorebook: dated by history; notes main: session clock only | the story's day on both; `historyEntryId` unchanged. A stale clock with the timeline off no longer dates the write. Backstop |
| links, `note-entry-knowledge`, stats, settle, message / scene stamps, Apply | — | verified unchanged (they store only `history_entry_id`, or already use story now) |

**Undatable lorebooks** behave exactly as before (tests pin entries, versions, held changes, links, knowledge ties).

★ **Correction 4, for the owner:** a lorebook with dated history and no clock counts as `dated`: its new Items begin at the newest history day and its updates (the Lair's included) are written as dated versions.
