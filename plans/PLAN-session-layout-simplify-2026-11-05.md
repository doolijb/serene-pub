## 1. Owner rulings (2026-11-05, quoted)

- R1 "Get rid of pin." — in the session AND in the editor.
- R2 "One type of group, each zone can have groups." — the canon's **panel** (NOMENCLATURE §9; *group* was retired for this 2026-10-14). Every zone (Left · Middle · Right) holds a stack of panels; a panel with 2+ widgets draws them as panel tabs.
- R3 Default = "center and two side rails" (the three zones). A "tabs + one side column" shell is a LATER option — **out of scope here**.
- R4 "No more pop-up widget settings. Settings are accessed through the layout settings." — settings only in the layout editor.
- R5 The **common default layout**: Middle = Messages tab + a character-management tab ("like an rpg character management screen": inventory, skills…). Left = compact data for each character (2nd tab: scenario / author's note management); bottom left = avatar/emote of the latest **character** that spoke. Right = world on top (2nd tab: lorebook management); bottom right = latest **persona** that spoke.
- R6 "Each genre will need its own twist on what's used and how busy the screen is."
- R7 "Make widget card backdrops global. Widget margin and background on its container/card is a css value that's provided by default to that widget that custom css can override/zero out. Card/backdrop preset and opacity can be set from the layout settings."
- R8 "Split the messages, composer and activity status/turn select into three widgets and introduce a fill/fit priority. … an expanding composer weighs more than the activity/turn, and it weighs more than the messages. … a fit composer with multiple [lines] drawn or actions folded out shrinks the messages widget."
- R9 "Another layout level setting, widget gap … Narrow, comfortable, spacious, or something along those lines."
- R10 (2026-11-05, during the build) "Also don't have most widgets show placeholder text when there's nothing to show. Messages being an obvious exception" — an empty widget draws nothing; Messages keeps its empty line; error states (*This widget stopped…*), a greyed control's reason, and owner buttons (Backdrop's Change) are not placeholder text and stay. Existing 🚧 **When empty** settings stay but default to nothing (lead decision).
- "Looks good" on the canvas (all boards as drawn), then "Go".

## 2. ★ decisions built as recommended (none questioned by the owner; each reversible — listed for the owner in the final report)

- ★1 The **rail of icons goes** with the pin: every panel is always open. Retire docked / in the rail / rail strip / `PanelRail` / fly-outs / tucked sides / Alt+[ Alt+] / Session panels sheet.
- ★2 **Zone switch**: when the sides don't fit beside a readable middle, and always on a phone, the session header shows a **Left · Middle · Right** switch; one zone shows at a time; starts on Middle. (Swipe is nice-to-have, not required.)
- ★3 A phone / full screen opens on the zone holding the first Messages panel, else Middle. The **primary panel** and **strips** go: the middle is a plain stack of panels like the sides. Rule kept: the middle is never empty (`MIDDLE_EMPTY`).
- ★4 Gaps: Author's note widget also edits the session **scenario** (shown as "Scenario"); Scene Portraits gains **Who** (*Characters* · *Personas* · *Both*, default *Both* = today) under Whoever spoke last; Stats gains a **one-character sheet** with a face picker (the Characters tab).
- ★5 Genre twists (shipped layouts; Story's World layout is KEPT, converted to v2 — challenger obj. 2): **Guide** = Messages + Composer only (Turn line optional). **Story** default = the common layout; Story's **World** layout stays (converted). **Lair** = party Stats left + last character; Story · Sanctum middle tabs; Places · Castellan's notes right + last persona; guest layout keeps Places · Party (Turn order + Who's here). **Dungeon Crawler** = middle tabs Planner · Story · Planning notes · Characters; left Party · Turn order + last character; right Journal · Table talk + last persona.
- ★6 Panel heights Fit / Fill / divider share stay.
- ★7 Backing drawn on the **panel** (tab strip on the card). The host gives each panel CSS custom properties `--sp-widget-margin`, `--sp-widget-background`, `--sp-widget-radius`, `--sp-widget-border` (🚧 names, §24); the SHOWN widget's style may override them (read from the style's declarations, the way `--sp-backing` is read today).
- ★8 Retire per-widget **Card**, Messages' **Auto / On / Off** backing mode and the style's `--sp-backing` preference. Default backing **Card, 100%**.
- ★9 **Widget gap** values **Tight · Comfortable · Spacious** = 4 / 12 / 24 px, layout-level, laid out by the host between panels and around zones. Default Comfortable. `--sp-widget-margin` defaults 0.
- ★10 **Priority** High · Normal · Low per panel beside Fit / Fill; default from the widget's declaration (Composer High, Turn line Normal, Messages Low, others Normal). When a zone runs short, Low gives way first, then Normal; Messages keeps a 160 px floor, past which the composer scrolls inside itself.
- ★11 A **Composer** writes to the Messages widget shown in its own zone (the open panel tab nearest above it); on a non-Messages tab it keeps the last channel shown and says *Writing to ‹channel›*. A zone with Messages but no Composer is a reading pane — retires Messages' **Show composer** / **Show messages** / **Composer position** (order is panel order).
- ★12 **Composer on the other tabs** stays, moved to the Composer widget.


## 3. Lead decisions on the fan-out's questions (2026-11-05, implementation calls inside the asked scope)

Recon reports (read them, they carry the file:line maps): `plans/briefs/RECON-layout-sdk.md`, `RECON-layout-runtime.md`, `RECON-layout-widgets.md`, `RECON-layout-storage.md`.

- D1 **Shape**: `panels: { version: 2, left: PanelV2[], middle: PanelV2[], right: PanelV2[], backing?, opacity?, gap? }`. The look lives INSIDE `panels` (top-level `look` is a retired document key). `PanelV2 = { key, tabs, open?, height?, priority?, title? }`; `priority` absent = the open tab's declaration, else `'normal'`. v1 stays readable; v2 is what is written.
- D2 **One converter, SDK-owned**: `panelsV2Of(layout, { widgetSettings, widgetStyles })` → `{ panels, settingsMoves, styleCopies }`. Pure, idempotent. Rules: drop `pinned`; middle = `[...above, primary, ...below]`; for each panel holding a Messages tab whose effective `showComposer !== false`, add a `turn-line` panel (fit; omitted when `nextUp === 'hidden'`) and a `composer` panel (fit) right after it (right before it when `composerPosition === 'top'`), ids derived from the first composing Messages instance (`messages` → `composer`/`turn-line`; `messages#sanctum` → `composer#sanctum`…; collision → `-2` per `resolveWidgetAlias`); skip when the layout already places a composer. Moves: Composer gets `composer`, `otherTabsComposer`, `showActions`; Turn line gets `nextUp`; drop `composerPosition`, `showComposer`, `showMessages`, `hostCard`, `backingMode`. No look is written (defaults: card, 100, comfortable). `showMessages:false` → the log simply shows.
- D3 **Ids** — a ruling reversal, recorded: NOMENCLATURE §23 (2026-09-16) "composer (the widget) — Merged into messages" is superseded by the owner's R8 (2026-11-05) "Split the messages, composer and activity status/turn select into three widgets". lay-F records the un-retirement in §23/§25. Un-retire `composer` (take it off `RETIRED_WIDGET_IDS`) and add `turn-line`; keep old-slot readers dropping a slot-era `composer` via a separate `LEGACY_SLOT_DROPPED` set so pre-0.6 blobs never revive one.
- D4 **Published names**: nothing removed. `PanelMiddleV1`, `DrawnMiddle`, `pinnedOf`, the `pinned` fields, `ZoneRung`/`DEFAULT_SIDE_RULES`/`zoneRungAt` stay exported, marked ⏳ deprecated until 0.7 (removal is the owner's call). Envelope `LayoutV1.pinned/collapsed/drawered` stay on the wire as true/false/false; `chrome.card` = "this panel's backing is not none".
- D5 **Prune order** (revised after challenger obj. 1): Messages SHEDS the moved fields (no hidden-field flag). The v2 conversion of stored rows (`convertPanelsToV2`, D14) runs from `dbReady` (src/lib/server/db/index.ts) immediately BEFORE `syncWidgetSettings(CORE_WIDGETS)`, under the same gate (dev boot / version change / fresh install); it accepts rows with old slots or v1 panels, so nothing is pruned before it is read. The existing steps 1–2 stay and become no-ops for converted rows (lay-E verifies the order and the no-top-level-await rule). Instance ids from the pure SDK helper `conversationSplitIds(instanceId)` (`messages`→`composer`/`turn-line`, `messages#x`→`composer#x`/`turn-line#x`; a v1 layout can never hold a `composer`, so no collisions).
- D6 **Widget declarations**: `WidgetDecl.panel?: { height?: 'fit'|'fill'; priority?: 'high'|'normal'|'low' }`; messages {fill, low}, composer {fit, high}, turn-line {fit, normal}.
- D7 **Composer target**: the host resolves it — the nearest panel ABOVE in the same zone whose open tab is a Messages copy; else the nearest Messages panel in its zone; else the layout's first Messages. If that panel is showing a non-Messages tab, keep the last channel and show *Writing to ‹channel›*. Messages announces its shown channel to the host (new core-only request `show-channel`). Turn line follows the same target. Line width follows the target. The selection bar stays inside Messages at its foot.
- D8 **Styles**: Composer and Turn line WEAR the effective style of their target Messages unless pinned their own; their parts keep `messages.compose*` / `messages.turn-line*` names ⏳ (aliases `composer.*` / `turn-line.*` added) so every existing style pack and user style keeps working.
- D9 **Backing**: drawn on the panel box (PanelTabs root = the card). Host sets `--sp-widget-margin` (0), `--sp-widget-background`, `--sp-widget-radius`, `--sp-widget-border` inline from the layout's backing + opacity; `declaredWidgetBox(skin)` reads those four from the SHOWN tab's style (vars, else CSS, last wins) and overrides. Dreamlit Cameo → background transparent + border none; Page line composer zeroes its background. Retire `--sp-backing`, `data-sp-backing`, `backingMode`, per-widget `hostCard` (pop-overs keep `HOST_CARD_CLASS`).
- D10 **Heights**: pure `allocateZone()` (app): floors first (Messages 160, Fit ≥ min(content,120)), then High wants, Normal, Low; Fill shares the rest; shares stay unless the zone overflows; unmeasured = today's CSS tracks. Host measures Fit content with a ResizeObserver on the widget root (Composer root must not be `block-size:100%`).
- D11 **Zone switch**: app-owned (`sessionZones.svelte.ts` + `ZoneSwitch.svelte`); on when sides don't fit beside a readable middle (from today's `tuckThresholdPx`) and always below `lg`; phone: its own row under the header; opens on the zone holding the first Messages panel; full screen shows that whole zone and no switch. Alt+[ / Alt+] go back to the app.
- D12 **Editor**: inline inspector pane (chosen tab → `WidgetSettingsPanel` + `WidgetStyleSection`; nothing chosen → Backing / Opacity / Widget gap); look edits go through `arrangeOps.setLook` (Undo/Cancel cover them); widget settings still write immediately (unchanged — noted, not done). Layouts-tab style overlay's Settings selects the tab in Arrange instead of opening a modal. Phone editor: three sections; settings as a pushed screen; "Layout settings" in the bottom bar.
- D13 **Widgets**: Scene Portraits `whoKind` (Characters · Personas · Both, default Both). **Both = exactly today** (characters + the viewer's own persona when *Include your persona* is on); **Personas** = every visible persona that spoke (any player's); **Characters** = no personas. A test pins the default (challenger obj. 5). Author's note gains a Scenario field (requests `session-scenario` / `set-session-scenario`; the app's answerer reads the session and writes through the EXISTING `sessions:update { session: { id, scenario } }` — no new socket event, challenger obj. 3; owner-only as there); shown even where the note isn't offered. Stats: a Characters tab = `stats` `arrangement: 'faces'`, `owners: 'all'`, PLUS sheet sections by the ruleset's groups and a portrait column (R5's "rpg character management screen").
- D14 **Storage**: no schema migration. `convertPanelsToV2` in `db/sessionLayoutPanels.ts`, called from `dbReady` before the prune (D5): rows with `panels.version = 1` on `session_panel_layouts` and presets `origin IN ('user','pub')`; one transaction per row (layout + moved `widget_settings` rows + `layoutSettings.widgetStyles` copies; stale `composer*`/`turn-line*` rows for that user+session deleted first); core rows reseed from the v2 catalogue; plugin rows convert at read/copy. `:set` / `layoutPreset:save` normalize v1→v2 server-side. Second-boot no-op test over all three tables.
- D15 **Story World layout KEPT**, converted to v2 (no shipped layout is deleted without the owner).
