## What was built

**1. ★client-3: a name in the session opens the cast member.**
- **Which presses:** everything on the session page that opens a person goes through the `open-character` request: a message's name, and a persona in **Who's here**. I took "the cast panel" to mean these. No other session-page press opens a person: Scene Portraits uses `view-avatar` and the turn order uses `pick-turn`.
- **New server read:** 🚧 **`lorebooks:memberOfSeat`**, a new handler `lorebookMemberOfSeatHandler` plus its `register` line in `src/lib/server/sockets/lorebooks.ts`. Its type is `Sockets.Lorebooks.MemberOfSeat` in `shared/sockets/types.ts`.
  - It takes `{ sessionId, ref }`. `ref` is a seat ref (`character:`, `seated-member:` or `player-seat:`) resolved with `seatOf`.
  - It is gated by `checkSessionAccess`, so the owner or a guest can ask. A stranger gets the session's existing not-found words.
  - It finds the member with `seatMembersAsRead`, wherever the member lives (the session's own book included); a seat with no card falls back to `memberAsRead`.
  - **`opensInBook`** is true when `lorebookAccessFor` returns owner or shared, and the book is not somebody else's session notes. That matches what the Lorebooks view can list.
  - **`sheet`** is sent only when `opensInBook` is false. It holds the name, nickname, shown name, face, and **`ownWords`**: the retold parts that are not in `followsCard`.
- **Client open flow:**
  - `castMemberOf` now asks the server through 🚧 `seatMemberOf` (`sessionPage/requests/seatMemberOf.ts`, using `awaitReply`). It answers with an address, `"sheet"`, or null.
  - `answerOpenCharacter` stays synchronous when its deps answer synchronously, so the existing tests are unchanged.
  - The new optional dep `openSeatMemberSheet` puts the ask in a consume-once store, ⏳ `sessionForms/seatMemberSheet.svelte.ts`, and opens the Sessions panel.
  - There, 🚧 `SeatMemberSheet.svelte` draws the read-only sheet in the detail pane.
  - Results: an address opens Lorebooks › Cast at the member. A seat with no member still opens the card.
- **Member page** (`CastWorkspace.svelte` and `CastMemberForm.svelte`):
  - **Edit the card** (optional prop `onEditCard`) appears in the card panel when the viewer owns the linked card and the book is not read-only for them.
  - When the viewer owns the card but `bookAccess !== "owner"`, the page shows the line _‹Member› lives in ‹Owner›'s lorebook ‹Book›; your card seeds them._ with **Edit my card**. Both sit outside the read-only fieldset.
  - Both buttons open the card in Character cards (`digest.characterId`).
  - `BookData` gained `bookName` and `ownerName`. `CastRow.character` gained `userId`.

All are in §25.
2. **How the sheet ask travels.** The house pattern is a `PanelsCtx.digest` key, but `src/app.d.ts` is outside this lane. I built a consume-once store instead and marked it ⏳. Recommendation: add `digest.seatMemberSheet?: { sessionId: number; ref: string }` and retire the store.
3. **New copy:**
   - _Nobody holds this seat now._ (the sheet, when the seat no longer seats anyone).
   - The guest line's fallback when the owner's name is unknown (e.g. a provided book): _‹Member› lives in the lorebook ‹Book›; your card seeds them._
   - The refusal _This cast member could not be read._
4. **A refusal can show twice.** `lorebooks:memberOfSeat:error` is not in Layout's `HANDLED_ERROR_EVENTS`, so a refusal is toasted as well as said in the sheet.
   - I kept it that way on purpose. The message-name press (`SessionMessage` does `void conv.request(...)`) has nowhere in place to say a refusal, so the toast is its only signal.
   - Recommendation: keep the toast. Adding the event to `HANDLED_ERROR_EVENTS` would make a refused name press silent.
5. **Widgets don't use a seat's portrait.** `projectCharacters` never applied a persona seat's portrait. Widgets show the member's face where the log shows the portrait. That is pre-existing for the portrait, but now visible with member faces. Recommendation: carry `portraitMediaId` into `Seat`.
6. **Gender-neutral wording.** The ruling's _your card seeds ‹them›_ is built as "them" everywhere, as briefed.
