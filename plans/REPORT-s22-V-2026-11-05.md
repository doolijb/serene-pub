## ★1 Where the fit is computed (built as recommended; the name is 🚧)
- **Server-side, on the existing list rows. No new event.** `rulesetFitReader(db)` (`src/lib/server/rulesets/genreFit.ts`) loads the offered genres **once per request**: `listOfferedGenres`, then each one's SDK declaration through `getGenre`.
- It keeps only the genres that declare `uses` or `rulesets: { only }`, and caches the answer per ruleset id. Rows never trigger their own queries.
- `rulesetFitByGenre(genres, ruleset)` is pure. It runs today's `rulesetFit` and maps the result exactly as `genreRulesOffer` does (`rating`, `reason`, `inWords`). There is no new calculation and no fit per preset.
- If loading the genres fails, the reader warns and returns no words. A fit never breaks a list.
- **Field `rulesetFitByGenre`**, not the brief's `fitByGenre`. The reason is R3: the canon already has *registration fit* and *template fit*, so the field is qualified. It is the same field with the same meaning on:
  - `rulesets:list` and `rulesets:detail` rows (`RulesetListRow`; registered rulesets only, so a draft-only row gets nothing);
  - `lorebooks:list` rows (`which === "books"`), for the book's own rules. A Freeform book gets none, through `adoptedBookRules`, the same rule the start form uses.
- The alternative was a client-side pure function. It was rejected because `rulesetFit`'s inputs (the genre declarations' `uses`, the ruleset declarations) are not on the client, and members never get the Rulesets list.

## ★2 Copy (each needs the owner's eye)
- **The `only` wording:** *‹genre›: Not offered*, with the why *(this genre plays only ‹A and B›)*. A ruleset inside the list shows its rating when the genre declares `uses`, and nothing otherwise.
  - Why this over *‹genre›: plays only ‹rulesets›*: the words sit on the row they are true for, they stay short in a one-line row, and the list moves into the why.
  - No core genre declares `only`. It is pinned by unit tests only (`genreFit.test.ts`).
- **The Freeform sentence:** *Freeform — the session chooses the rules* (the brief's words).
- **The why format:** *Lair: Good (a health-like number — told in words)*, both in the line's hover title and in each unfolded item. The w2 brief's `Lair: Good: reason` rendered a double colon, so the supervisor changed it to the parenthesised form.
- **Admin › Rulesets column label:** *Genre fit*, placed after **Plays**.
- **Rating words:** the start form's (Incompatible, Poor, Ok, Good, Great, Perfect) plus *Not offered*.

## ★3 The book **list row** is queued for the lead (not built: `LorebookListItem.svelte` is not this lane's)
The server already sends `rulesetFitByGenre` on every `lorebooks:list` row, and the component is ready. Only the row has to draw it.

**Tension:** STYLE-GUIDE §6.4 says "A row is two lines and a face". The lorebook row already uses its second line for the description, or for the share/provided line. A third line breaks that anatomy, and nearly every book is Freeform, so most rows would carry the Freeform sentence.

**Recommended:** the line as the row's second line **only when the book has no description and no share line**, and always as the row's hover (`title`). Book settings shows the full words with whys.

**Alternatives:**
- an always-present third line (breaks §6.4);
- MetaLine facts after the description lead, so the description truncates first.

The hunk for the recommended option, in `src/lib/client/components/listItems/LorebookListItem.svelte`:
```svelte
import RulesFitLine from "$lib/client/lorebooks/RulesFitLine.svelte"
import { isFreeformBook } from "$lib/client/lorebooks/rulesFitWords"
…
{:else if lorebook.description}
  …existing…
{:else}
  <RulesFitLine fits={lorebook.rulesetFitByGenre} freeform={isFreeformBook(lorebook.primaryRuleset)} />
{/if}
```
The docs sentence that goes with it, for `docs/lorebooks.md` near l.277: "A book's row says how each genre takes its rules when it has no description, and on hover."
