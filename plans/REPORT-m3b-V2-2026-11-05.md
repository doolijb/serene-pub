## Landing rule (★M3b-W-1/W-2)
A session that **can't write its book** — it reads no book, or reads a book its owner does not own (a member's session on a pub-wide/provided or shared book) — keeps its world-scope values in its own book (Session notes). Test: 🚧 `keepsValuesInOwnBook(db, sessionId)` (`lorebooks/ownBook.ts`; `loreWriteRoute`'s ownership rule with the mode set aside, read as `loreWriteBookIdOf` reads; not `findOwnedBook`, whose static `$lib/server/db` import defeats test `vi.mock`). In such a session `worldOwnerOf(db, sessionId, owner, userId)` files a world value (`session`) on the own book's `lorebook` row and a seated character's value on that character's cast member row in the own book (held by the attached book or not; a player's seat with a persona = that persona). The attached book gains no binding or value row. The owner's own book: unchanged (book, under Full/Review/Off; shared between the owner's sessions); a character that book doesn't hold still lands in the own book (m3b-W).
**Writer first:** `worldOwnerOf` takes the writer (`socket.user.id` from `state:set`; `null` from a run = the session's owner) and, before making any own-book row, checks (1) the character is seated, (2) the writer may write the own book's `lorebook` row (`assertSessionOwner` → `assertBookWriter`). A guest's refused write makes nothing. `assertSessionOwner`'s `lorebook` branch admits the own book's row (`lorebooksReadBy(...).ids`) — closes last night's "no book can't keep world values" gap.
