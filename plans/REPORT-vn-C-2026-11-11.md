## Stopped on

**S1. "The whole bar is Next line's target" cannot be done in the component.**
- `sdk/src/hostElements.ts` forwards `click` only from `button`, `a` and `sp-*` host elements (`REDELIVERED_EVENTS = ['click']`); a component's `<div onclick>` never fires.
- Built: the bar is a plain container; **Next line** is the real button.
- Proposal, no SDK change — vn-B's CSS stretches the button across the bar: `[data-widget-part~="dialogue-box.bar"]{position:relative}`; `[data-widget-part~="dialogue-box.next"]::after{content:"";position:absolute;inset:0}`; Pause above with `position:relative; z-index:1`.

**S2. ★ A hidden Messages Log tab autoplays the newest line.**
- App `PanelTabs.svelte:18`: every tab stays mounted, inactive ones hidden. App `uiWorkers.ts:2-4`: one UI worker per owner, so core widgets share `globalThis.__spAutoplayed`.
- Only under **Read aloud: Make and play** with playback `auto`: (a) while the box holds an older line the hidden Log plays each newer line's voice as it arrives; (b) the page plays one sound at a time, so a Log voice pauses the box's player and the box treats that as a hold; (c) when the newest line is the one shown, whichever SpokenLine decides first plays it — if the Log wins, the box hears no `play` and after 5 s runs the reading timer.
- Proposal: while a Dialogue box is placed, the page (`sessionPageProjections`) gives each Messages copy's dossier a playback that does not autoplay (e.g. `spokenPlayback:'click'`), so the box's shown line is the only automatic voice. Host data only; no change to Messages' code.
- Alternatives: drop the Log tab (conflicts with plan §1.6); accept and document.
