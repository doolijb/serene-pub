## 0. What this is

A second managed service beside KoboldCPP: Serene Pub downloads the audio.cpp binary, downloads
the speech (and transcription) model packages, writes audio.cpp's `server.json`, starts and
supervises the process, and exposes it as ONE connection, **audio.cpp, run by Serene Pub**, whose
models fill the **Narration** loadout (speech) and the **Transcription** loadout (hearing). The
existing external `audiocpp` type stays for people who run their own.

## 1. audio.cpp facts the plan rests on (v0.9.3, 2026-10-26; looked up 2026-10-28)

- **Binary.** GitHub `0xShug0/audio.cpp` releases, Apache-2.0. Assets `audio-v<ver>-bin-<os>-<arch>-<backend>[-portable].{tar.gz,zip}`:
  ubuntu-x64 cpu / cpu-portable (63 MB) / vulkan / vulkan-portable (77 MB) / cuda12.8-colab;
  windows-x64 cpu / cpu-portable (30 MB) / vulkan / vulkan-portable (82 MB) / cuda12.4 / cuda13.3 / rocm-test;
  macos arm64 / x64 metal (35 MB). **Windows CUDA needs the matching `cudart-*` archive (575–607 MB)
  unpacked beside the binary.** No Linux arm64. The archive holds `audiocpp_server`, `audiocpp_cli`,
  `audiocpp_gguf`, **`model_specs/*.json` (130 families)** and `tools/`. **No `audiocpp_model_manager`
  in prebuilt archives** (opt-in CMake build only) → Serene Pub downloads packages itself.
- **Packages.** Each `model_specs/<family>.json` has `package_defaults.download = {kind: huggingface_snapshot, repo: "audio-cpp/audio.cpp-gguf", revision: main}` and `packages[] = {id, display_name, default?, format, precision, target_directory, files[], strip_prefix}`. Files are repo-relative paths; after `strip_prefix` they land in `<models>/<target_directory>/`. Speech packages of interest are single GGUFs: `kokoro_82m_q8_0` (Kokoro-82M-GGUF), `qwen3_tts_1_7b_customvoice_q8_0` (2.8 GB), `qwen3_tts_0_6b_base_q8_0` (2.0 GB), `kitten_tts2_*`; ASR: `parakeet_tdt_*` (0.6B v3 q8, the shipped example), `qwen3_asr_*`. **No sizes or sha256 in the spec**; sizes come from the HF file listing.
- **Config.** `audiocpp_server --config server.json [--log --log-file …]`. Keys used: `host, port, backend, device, threads, lazy_load, max_loaded_models, idle_unload_ms, ui, ui_management, voice_dir, models[]`; model entry `{id, family, path, task: tts|asr|vdes, mode: offline, default_voice_preset?, voice_presets?, default_request_options?}`. A config change means **rewrite + restart**; there is no admin reload route for configured entries. Lazy load + `max_loaded_models` LRU means audio.cpp owns residency (fits the model-lane rule: never couple a queue to residency).
- **Routes.** `GET /health {status, backend, models, version, git}` (does not mean a model is loaded), `GET /v1/models [{id, configured, device}]`, `GET /v1/audio/voices?model=`, `POST /v1/audio/speech` (the dialect the external profile already speaks), `POST /v1/audio/transcriptions` multipart `file`+`model`(+`language`) → `{text, timing}`; `/details` adds segments/words. `POST /v1/tasks/unload_models {model_ids}`.
- **Backends.** CPU, Vulkan, CUDA (the optimised path), Metal. Kokoro is CPU-fine; Qwen3-TTS 1.7B and Kitten 2 want a GPU (published RTF only on CUDA).

## 2. Design decisions (D1–D10)

- **D1 Own type, own table.** `CONNECTION_TYPE.AUDIOCPP_MANAGED = "audiocpp_managed"`, manifest `text->audio: native`, `audio->text: native`. New single-row table `audiocpp_settings` (enabled, binary dir, binary variant, release tag, port, models dir, backend, device, threads, max loaded, idle unload ms, subprocess timeout). ⚠ Not columns on `koboldCppSettings`.
- **D2 Port 5002 by default.** audio.cpp's own default 8080 collides with llama.cpp in local discovery. Settable like KoboldCPP's.
- **D3 Task and family are DATA in the list repo, never read from the binary (owner 2026-10-28: "we need a durable solution").** Two files in `SerenePub/serene-pub-gguf-list`:
  - **`audio.yaml`** — the recommended audio models, same discipline as `recommended.yaml`: `name` (HF repo), `files[]` (repo-relative, as audio.cpp's spec lists them), `task: tts | asr | vdes`, `family` (audio.cpp's family id, e.g. `qwen3_tts`, `kokoro_tts`, `kitten_tts2`, `parakeet_tdt`, `qwen3_asr`), `variant` (`customvoice`, `base`, `voicedesign`, …), `size`, `recommended_vram` (0 = CPU-fine), `license`, `tags` (`instruction-voices`, `preset-voices`, `streaming`, `multilingual`, `opt-in-notice`), `details.description`. Seeded ONCE from audio.cpp's `model_specs/*.json` by a maintenance script kept in the list repo (`tools/from-audiocpp-specs.py`), then hand-curated; the app never parses a spec file.
  - **`audio-families.yaml`** — the detector's rules, one entry per family: `family`, `tasks[]`, `runner: audiocpp` (later `koboldcpp` for the families its loader takes), `match: { repos: [regex], files: [regex], gguf_architectures: [string], hf_pipeline_tags: [string], hf_tags: [string] }`, and `voices: catalogue | listed | none` (which tells the speech facts where voices come from). Updated when a family appears upstream, without an app release.
  - The app reads both through the existing `recommendedGguf.ts` reader (one fetch at boot, cached, with the last good copy kept in `system_settings` as today — ★A10 on a shipped fallback for first boot offline).
- **D3c One family detector, `server/audio/familyOf.ts`**, used by every path a speech or transcription model can arrive on: (a) `audio.yaml` entries carry it outright; (b) **Hugging Face search** in the model finder: HF `pipeline_tag` (`text-to-speech`, `automatic-speech-recognition`) + `tags` + repo id + sibling filenames through `audio-families.yaml`'s `match`; (c) **files already on disk or copied in by hand**: the GGUF header's `general.architecture` / `general.name` (the app already reads it in `koboldcpp/modelKind.ts`) and the filename, same rules. The result is `{ task, family, variant?, confidence: listed | matched | guessed }`; `guessed` is shown as *Looks like Qwen3-TTS — confirm* and never auto-enabled. Unmatched audio files are listed under *Unknown family* and cannot be enabled (audio.cpp refuses a wrong family anyway). The Models tab's grouping is the detector's answer: **Speech** / **Transcription**, then family.
- **D3b Models folder = audio.cpp's organisation, under an `audio` tree (owner 2026-10-28).** `<models>/audio/<task>/<family>/<target_directory>/<files after strip_prefix>` — e.g. `models/audio/tts/qwen3_tts/Qwen3-TTS-12Hz-1.7B-CustomVoice-GGUF/qwen3-tts-12hz-1.7b-customvoice-q8_0.gguf`, `models/audio/asr/parakeet_tdt/…`. The leaf is audio.cpp's own package directory name, so a person can point their own audio.cpp (or its `audiocpp_model_manager --models-dir`) at any leaf unchanged, and a package copied in by hand is recognised by walking the tree and matching `target_directory` + `files`. `task` and `family` come from the spec (`tasks[0]`, `family`), never from the file name. KoboldCPP's text/image folders are untouched; its speech GGUFs stay where its loader finds them (★A8 asks whether KoboldCPP's TTS files should move under `audio/` too).
- **D4 Download = HF snapshot of `files[]`** through the existing chunked HF downloader (sockets/koboldcpp.ts `downloadFileInParallelChunks`, lifted into `server/net/hfDownload.ts`), into `<models>/<target_directory>/`. `notifyDownloadSettled` gains source `"audiocpp"`. Downloads tray gains a fifth feed.
- **D5 One `server.json` Serene Pub owns.** Every downloaded package that is *enabled* becomes a `models[]` entry with `id = package id`, `family`, `path`, `task` (tts / asr; `vdes` for VoiceDesign), `mode: offline`, `lazy: true`. `lazy_load: true`, `max_loaded_models: 2` (one tts + one asr), `idle_unload_ms` from settings, `ui: false`, `host 127.0.0.1`. Rewritten on every change; the supervisor restarts the process when the file's hash changed since spawn. **No voice_dir** (no cloning, by ruling).
- **D6 Binary variant pick.** Default per platform: linux → `cpu-portable`, `vulkan-portable` offered; windows → `cpu-portable`, `vulkan-portable`, `cuda12.4`/`cuda13.3` (+ auto-fetch of the matching `cudart` archive as a second asset of the same job); macOS → `metal` for the arch. The picker explains why (CPU for Kokoro; GPU for Qwen3/Kitten). Checksums: verify when the release publishes a `.sha256`/`SHA256SUMS` asset, else record "unverified" as KoboldCPP does (`binaryManager.ts:363-384`). ★A1 asks whether to require it.
- **D7 Supervisor factory, not a clone.** Extract from `koboldcpp/subprocessManager.ts` the service-neutral part — PID file, adopt/orphan sweep, process-group SIGTERM→SIGKILL, single-flight start, stale-`starting` respawn, idle timer, health check, `globalThis` state keyed by service id — into `server/managed/supervisor.ts` `createSupervisor({id, binaryPath(), args(), port(), ping(), onSpawn?})`. KoboldCPP keeps its behaviour by being the first caller; audio.cpp the second. Same for the per-user emitter refcount map (`server/managed/emitters.ts`, replacing the three copies). The binary downloader is cloned on `net/githubReleaseDownload.ts` (signal + progress) parameterised by repo and asset filter; KoboldCPP's stays as is this release.
- **D8 Speech adapter = existing profile + `withManagedReady`.** `profiles/audiocpp.ts` gains `audiocppManagedSpeech` exactly as `profiles/koboldcpp.ts:204-257` does: ensure binary + config + process, then the dialect. Base URL comes from `audiocpp_settings`, the row's is display-only.
- **D9 Transcription adapter.** `transcriptionAdapters/AudioCppTranscriptionAdapter.ts` on `BaseTranscriptionAdapter`: multipart `file`+`model` to `/v1/audio/transcriptions`, `language` when the attachment or session says one; registered for both `audiocpp` (external) and `audiocpp_managed`. Fills the **Transcription** loadout; `attachments/transcribe.ts` already dispatches `audio->text`.
- **D10 Surfaces mirror KoboldCPP's, named audio.cpp.** Add menu: *audio.cpp, run by Serene Pub*; `ManagedKind | ManagerKind | ModelManager.panel | DestinationKind | EndpointKind | DownloadSource` all gain `"audiocpp"`; the managed connection view gets stages `acpp-binary → tabs` with Models (packages: Available / Downloaded / Enabled, Speech and Transcription groups), Process (status, loaded models from `/v1/models`, backend/version from `/health`, Restart, Stop), Settings. Admin connection IdPage embeds the runtime block as it does KoboldCPP's. Local discovery adds audio.cpp on :8080 and :5002 but leaves out the host the managed row addresses. Members never see any of it.
