## Background (stage S2 of "sessions seat cast")
A session **seats cast members**; each character seat (`sessionCharacters[]`) holds a card (`cc.character`, `cc.characterId`) and, since S1, its cast member's id (`cc.castMemberId: number | null`, already on every seat entry of `sessions:get` and `sessions:list` — it is a column of the seat row). What a seated character *is* (name, face, sprite sets) is the member as read, own over card. **Keys and requests stay keyed by card id** (`character:<cardId>` refs out, `spriteSetOverrides` by card id, …) until S4. Nothing a user sees changes for today's data (a member with no own name/face/sets reads exactly as its card).

### The payload contract (the supervisor builds the server half; build against these types, already in `src/lib/shared/sockets/types.ts`)
- `sessions:get` session: `castNames?: Record<cardId, { ownName, ownNickname }>` (the seat's member's name and nickname as read, present only when they differ from the card's; read with `memberShownName`), `castFaces?: Record<cardId, filesId>` (the member's face when it retells it), and new 🚧 `castSpriteSets?: Record<cardId, SessionSpriteSet[]>` (present only when the seat's member has sprite sets of its own with images; same shape as `cc.character.spriteSets`).
- `sessions:list` rows: now also carry `castNames` and `castFaces` (same meaning).
- The client already has `castNameOf(session, id, card, fallback)` and `castFaceOf(session, id, opts)` in `src/lib/client/components/sessionPage/projections/characters.ts`, and `withMemberNames` in `$lib/shared/lorebooks/memberIdentity`. Many page sites already use them; others still read the bare card.
