## Final names (for m3b-C and mundi-M3b-S)
- **SDK declaration**: `SessionShape.castFromLorebook?: { field?: string }` 🚧 (`@serene-pub/sdk`, `sdk/src/descriptors.ts` 1029–1046). It means: seat the attached lorebook's cast at create. `field` names a declared `boolean` field of the same shape, which switches it per session. With no `field`, it is always on for this genre. `genre()` refuses (`sdk/src/genres.ts` 1114–1135), each time with a sentence prefixed `<id>.shape.castFromLorebook`:
  - a value that is not an object;
  - an empty or non-string `field`;
  - a `field` not declared in `shape.fields`;
  - a `field` that is not boolean;
  - a shape with no `lorebook`;
  - a shape with no `characters`, or `characters.max: 0`.
- **Socket shape**: the `sessions:genres` row's `shape.castFromLorebook?: { field?: string }` (`src/lib/shared/sockets/types.ts` ~6642). `genreRowFor` already sends the shape whole.
- **SDK request field**: the `'create-session'` params gain `persona?: { name: string; description?: string }` (`sdk/src/widgets.ts` 2068–2078).
- **Constants**: `CREATE_SESSION_PERSONA_NAME_MAX = 80` and `CREATE_SESSION_PERSONA_DESCRIPTION_MAX = 2000` (`sdk/src/widgets.ts` 1455–1460). They count characters after trimming. They are exported from `@serene-pub/sdk` through the existing `export *`, which is why `index.ts` is unchanged. The SDK only documents the limits; the client enforces them.
- **Server helper**: `bookCastToSeat(db, { lorebookId, userId, isAdmin, exclude })` in `src/lib/server/sessions/seatBookCast.ts`. `sessions:create` gets no new event and no new param. The seated cards arrive as ordinary `sessionCharacters` in the create reply and in `sessions:get` (`getSessionFromDB` has no filter by card owner, so a member sees the admin-owned seated cards).

## Behaviour built
`sessionsCreateHandler` (`sockets/sessions.ts`, additive hunks):
- **Captures the declaration** (~905–985): it keeps the genre's `castFromLorebook`, the floored shape and the declared fields.
- **Decides whether to seat** (1059–1093), after the genre-field filter and outside the create transaction. Seating happens only when all of these hold:
  - the genre declares `castFromLorebook`;
  - the switch is on. With no `field` it is on. Otherwise the stored `genreFields[field]` decides, falling back to the field's declared `default`. Only `=== true` counts, so an unset field with no default is off (P1).
  - a book is attached. For `new-world` this is the chosen source, which carries the same cards as the copy.
- **What `bookCastToSeat` returns** (the book's members in book order, each member's first card):
  - **Access:** a provided-marked book must be in `providedBooksReadableBy`, so a disabled or ownerless one seats nothing, even for the admin owner. Any other book needs `lorebookAccessFor ≠ null`.
  - **Dropped:** persona cards. For a provided book, any card whose provided mark names a different plugin than the book's. Any card the request already seats as a character or a persona. Duplicates.
- **Shape check:** the seated cast counts toward `characters`. `shapeViolations` is re-run with the seated cast added, and a violation refuses with the existing sentence.
- **Writes:** `isGroup` counts the seated cast. The seated rows are inserted after the picked characters, in book order, before `runLorebookBindingCheck`.
- **Not done anywhere else:** nothing seats on `sessions:update` or attach. There is no ledger row and no server-side persona creation.

`runLorebookBindingCheck` (~5625–5637): after the existing ownership gate, a book with a genuine provided mark returns early. No member rows go into a provided book for anyone, the enabling admin included. Because the gate covers every caller, it also applies to `summarize.ts:611`, `import.ts:936` and `lorebooks.ts:4252`.

## §25 change-ledger rows (for the NOMENCLATURE owner, m3b-C; text to paste)
- **`castFromLorebook`** (`SessionShape.castFromLorebook?: { field?: string }`) 🚧, 2026-11-05 (PLAN-sdk-creation-seams §23, owner ★M3-4 "The book seats its cast, genre-declared").
  - **What it is:** a genre's declaration that, at session create, the attached lorebook's cast members are seated as the session's characters (character seats), in book order, whoever owns the cards. A persona card is never seated. For a provided book, only its provided-marked cards are seated. `field` names the genre's boolean switch field.
  - **What it is not:** `characters: { min }` (a bound on picks), a cast binding (the member ↔ card link), the start form's character picker, or anything that happens on update or attach.
  - **Who owns what:** the SDK declares it; core's `sessions:create` acts on it (`bookCastToSeat`).
- **`create-session.persona`** (`{ name, description? }`) 🚧, 2026-11-05 (§23, owner ★M3-3).
  - **What it is:** an applet's proposed player. The start form offers it as a new persona, and the card is made only on the person's Start, as their own.
  - **What it is not:** a persona card until then, and never created by the server from the request.
  - **Limits:** `CREATE_SESSION_PERSONA_NAME_MAX` (80) and `CREATE_SESSION_PERSONA_DESCRIPTION_MAX` (2,000) characters.
- **`bookCastToSeat`** (`server/sessions/seatBookCast.ts`) 🚧, 2026-11-05.
  - **What it is:** the one decider for which cards a book seats at create: book order, never a persona, a provided book's own marked cards only, gated on the book's read access.
  - **What it is not:** the binding sync (`runLorebookBindingCheck`, which links cards to members).

## Decisions I made (inside scope; named per CLAUDE.md §Decisions)
1. The seated cast counts toward the shape's `characters` bounds. When seating would pass a declared `max`, the create is refused with the existing "does not fit" sentence; nothing is silently trimmed (P1).
2. `genre()` also refuses a declaration that could never seat anyone: one with no `lorebook`, or with `characters` absent or `max: 0`.
3. A provided book seats only cards whose mark names the **same plugin** as the book's mark.
4. An unset switch field with no declared `default` is off.
5. For `new-world` the seats are computed from the chosen source book. Its cards are the copy's cards.
6. **The binding-check gate returns early for a provided book** (scope review, finding 2). Besides minting no rows, it no longer refreshes the cast list and no longer asks the admin owner about orphaned bindings for that book from a session. I recommend keeping this: the cast is the plugin's, changed only through its write mode, so asking the admin about it from a session invites an edit outside that mode. **★m3b-D-1:** keep the early return, or narrow the gate to the two minting loops?

## Open ★
- **★m3b-D-1:** the binding-gate breadth (above). My recommendation is to keep it. The trade-off is that an admin's session no longer asks about a provided book's orphaned rows; the admin can still open the book.
- **★m3b-D-2 (from the scope review):** a genre with `castFromLorebook` together with `characters: { min: N > 0 }`. The first shape check runs before seating and counts only the person's picks, so a person who picks nothing is refused even when the book would fill the seats. The port declares `min: 0`, so nothing hits this today.
  - Recommend: count the seated cast in that first check. This means moving the seat computation ahead of it, so the switch value is read before `resolveAtStart`.
  - Alternative: have `genre()` refuse `min > 0` beside `castFromLorebook`.
  
  Not built; this is your call.
