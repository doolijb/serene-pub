Two small things the client works around, named so s22-S can decide (neither is needed for this lane):
1. **A book row's ruleset name.** `lorebooks:list` rows carry `primaryRuleset` (an id) but no name. The start form names a book's rules from the genre's offer (`rulesOffer.choices`), which lists every pickable ruleset for a `recommended` genre — so the only books it cannot name are ones on a retired/unregistered ruleset, or (for an `only` genre) ones outside the list. The client says *Rules of its own* / the `only` refusal sentence for those. Optional: a `rulesName` on the list row (and kits already carry `rulesName`).
2. **A preset that locks the ruleset** (`atStart.locked` includes `ruleset`, sessions.ts ~1186) is taken by the server "whatever was sent", but the start form is never told, so it offers a rules choice the server overrides (P1: a hidden decision). Today's Rules card has the same hole; not made worse here. The client could read it from `preset.settings.ruleset` via `settingValueOf` (as `presetRigour` does) — ★ for the owner whether the pick should then say *Set by preset ‹name›* (★§22-3's words).
