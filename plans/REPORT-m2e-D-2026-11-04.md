### 1a. Where "disabled" lives (one decider)
- Correction to the brief's premise: **there is no stored `core` plugin row**. `notCoreRow()` (`frameHost.ts:329`) and `store.ts notCore()` treat a row under `core` as a stray to remove, and `pluginIdFindings` refuses the id. So core's primers have no `plugins.provided` json to keep a mark in.
- Decision (implementation, inside scope, no column): the disabled mark lives **on the book's own provided mark** — `lorebooks.extra_json.provided.disabled: true` — for every owner (core primer rows and plugin books alike). Readers check ONE predicate (the mark is the row's own — `uuid` matches — and `disabled` is true). The plugin row's json keeps a mark only for a slug that has **no row yet** (`plugins.provided.disabled[slug]`, what the boot pass turns each `dismissed[slug]` into); the next sync imports that book with `disabled: true` on its mark and drops the ledger entry in the same write.
- A book kept by uninstall (`providedBooks: 'keep'`) is no longer provided for delete/hide purposes once its plugin row is gone (the owner check fails); uninstall-keep clears `disabled` on the books it keeps, so nothing stays hidden with no page to show it again.

### 1b. Lorebook rows
- *(landed)* `lorebooks:list` row (and the lorebook `lorebooks:get` returns) gain
  `provided?: { disabled: boolean }` — **present exactly when the book is a provided book** (a plugin's provided book or a core/plugin primer row, its mark genuine and its owner present); absent otherwise. A disabled book is **not in** `lorebooks:list` at all (the server hides it), so in the list `disabled` reads `false`; `lorebooks:get` of a disabled book a session reads returns it with `disabled: true`.
- Lane C: hide Delete wherever `provided` is present. `lorebooks:delete` on one is refused with `PROVIDED_BOOK_DELETE_REFUSAL` (server, `src/lib/server/plugins/providedMarks.ts`): _"A lorebook that comes with the pub or a plugin can't be deleted; an administrator can disable it to hide it everywhere."_ (copy 🚧).

### 1c. Plugin page

### 1d. The disable/enable event pair (admin only, `plugins:*` family) — *(landed; types `Sockets.Plugins.SetProvidedBookDisabled`; listed in `src/lib/shared/sockets/interest.ts`'s admin `plugins:` list, NOT in `SCOPED_EVENTS`; lane C must add both to `src/lib/client/sockets/typedSocket.ts`)*

  - Params: `{ pluginId: string; slug: string }` — `pluginId: "core"` names core's primers; a primer row's `slug` is its primer id (`core:primer/ninth-mile@1`).
  - Response: `{ pluginId: string; slug: string; disabled: boolean; lorebookId: number | null }`.

A `"core"` slug with no row is refused ("No such provided book."), nothing written. Lane C's domain context listens to both events (the only listener, the only toaster).
