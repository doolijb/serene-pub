**Grammar (`sdk/src/participants.ts`)**
- `ParticipantRef` gains 🚧 `` `seated-member:${string}` ``.
  - I used `${string}` rather than the brief's `${number}`, to match the sibling kinds and the "ids are opaque" rule (the plan in §29 also says `${string}`). The parser checks the id the same way it checks the others.
- `ParsedParticipantRef` gains `{ kind: 'seated-member'; id: string }`.

- Both refusal sentences name it: `… character:<id>, seated-member:<id>, player-seat:<id>, envoy:<slug>` and `(user, character, seated-member, player-seat, envoy)`.

**Seat rows of the cast read (`SessionCastV1`)**
- Each `sessionCharacters[]` and `sessionPersonas[]` row gains three optional fields:
  - `ref?: ParticipantRef`
  - `castMemberId?: number | null`
  - `cardId?: number | null` — the member's active card on the timeline.

**Owner kinds**
- `OwnerRefV1.kind` is now `'session' | 'session_cast' | 'seated_member' | 'player_seat' | 'session_location'`.
- `TurnOwner.kind` is now `'session' | 'session_cast' | 'seated_member'`.
- I added 🚧 `TurnMessage.castMemberId?: number | null`. `openAnchorFor` matches a `seated_member` owner on `castMemberId` only, never on `speakerId`, because card ids and member ids share one number range. Without this field the new kind could only have been matched on the wrong id.

**Messages and turn order**
- `MessageV1.castMemberId?: number | null`, `ChannelLaneV1.latest.castMemberId?: number | null` and `TurnHistoryMessage.castMemberId?: number | null` (★S3-3).
- The three turn-order readers each gain one optional trailing argument:
  - `senderRefOf(m: Pick<TurnHistoryMessage,'personaId'|'castMemberId'|'speaker'|'metadata'>, refOfMember?: (castMemberId: number) => ParticipantRef | null | undefined): ParticipantRef | null`. The return type widens from `` `character:${number}` | `player-seat:${number}` | null ``.
  - `spokenRefsSince(messages, refOfMember?)` returns `Set<string>`.
  - `roundRobinOrder(candidates, messages, refOfMember?)` returns `TurnEntryV1[]`. I added the argument here too, passed straight through; otherwise core's round robin could never use the lookup.
- How the lookup behaves:
  - It changes only **who** a row names, never whether the row counts. An assistant row never becomes a sender.
  - A missing lookup, or one that finds nothing, falls back to today's card form.
  - With no lookup the output is byte-identical to today.

**Scene Portraits and sprite choices**
