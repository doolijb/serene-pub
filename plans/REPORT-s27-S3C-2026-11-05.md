### Host-filled fields
**Values on today's data:**
- `ref` is `character:<held card>` for a character seat or a carded player seat, and `player-seat:<id>` for a card-less player seat.
- `castMemberId` is the seat's stored member (`seatMemberId`), never `CastMemberLink.castMemberId`.
- `cardId` is the member's active card on the timeline. With no member read it is the held card; for a card-less seat it is null.

**Where they are filled:**
- `state/resolve.ts`: the `cast.byId` entries. `CastMemberLink` gains `seatActiveCardId`; `PlayerSeatLink` gains `seatMemberId` and `seatActiveCardId`. This reuses the member read `seatedCastOf` already makes.
- `host.ts` `case "session_cast"`: the `sessionCharacters[]` / `sessionPersonas[]` rows. It uses one `seatMembersAsRead` per seat set, plus one `membersAsRead` batch for card-less seats that store a member. `sessions/settings.ts` `readCast` goes through this read, so it is filled with no edit.
- `sockets/sessions.ts` `withSessionExtras`: the `sessions:get` seat rows (w3). It reuses the existing member read. `Sockets.Sessions.Get.Response` rows gain `ref?` and `cardId?`.
- `sockets/state.ts`: owner rows gain `ref` and `castMemberId` (★S3-2). `StateOwnerRow` in `types.ts` gains `ref?` and `castMemberId?`, and its `kind` admits `seated_member`. A local, non-exported `BuiltOwnerRow` alias keeps the built rows narrow.
- `castMemberId` on messages and choices:
  - `ChannelLaneV1.latest`: `sessions:channelLanes`.
  - `turnMessages` rows: `state/write.ts`, which feeds `openAnchorFor`.
  - The host's history rows: `toMessage` in `host.ts` (my edit, from w2's queue). It is set only when the row is stamped, so unstamped rows are byte-identical.
