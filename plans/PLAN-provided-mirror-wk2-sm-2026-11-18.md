## 1. WK2 — a lock passes added art (lane `small-5`, part A)
Owner: "A lock stops runs changing the cast member's details and sheet; art a run makes is still added".
- Runs add art through two outlets only, both on a member's card action: `core:outlet/offer-media` (lock check `pipelines/runtime/host.ts` 5567–5589; write `offerMediaToMemberGallery`, `characters/portrait.ts` 199–272 → `addToMemberGallery`, `media/index.ts` 676; inserts `cast_member_files` rows only) and `core:outlet/attach-sprite` (lock check `host.ts` 5657–5681; `attachGeneratedSprites`, `sprites/attach.ts` 95–202 → `placeSpriteFile`, `sprites/index.ts` 400–444).
- No run sets the face: `lorebook_bindings.face_media_id` is written only by person doors and the story-write funnel, which refuses a locked member (`characters/versions.ts` 1893). So after the fix an image lands and a face change is still refused with the existing note.
- Fix: delete the `offer-media` lock block; the sprite outlet passes the lock too, but for a locked member it never creates-as-default or flips `isDefault` on an existing set (`ensureDefaultSpriteSet`, `sprites/index.ts` ~133–157) and says so in the run's `notes`; reword the `castMemberLockedAgainstRuns` comment (`shared/lorebooks/runLocks.ts`).
- Tests: `cast/castMemberLock.int.test.ts` 461– flips; new: a locked member's gallery grows and `faceMediaId` is unchanged; a locked `update-cast-member` carrying a face is still refused with the note. Docs `docs/lorebook-cast.md` 61; NOMENCLATURE row ~413, §25. Back never removes this art, locked or not.

## 2. AP6 + AP7 + AP1 (lanes `ap-4a` plugin mirror + card reuse, `ap-4b` core starters, `ap-4c` hand-edit doors)
Owner: AP6 "Remove both: the lorebook becomes exactly what the source ships"; AP7 "Extend the refresh to all of it" + "And drop deleted rows"; AP1 "…can't mutate or delete them, only disable them or remove the plugin. To mutate, the admin/user clones it first"; AP5 "A users own custom starter lorebook is their own, unchanged."

**Today.** `plugins/providedBooks.ts` `upgrade` (1355–1469) diffs entries by `mark.entries`; `upgradeCastAndStats` (1084–1328) cast (`mark.cast`) and template stat values (`mark.stats`); `upgradeRules` the two ruleset columns. Gone-upstream rows are only counted (1272, 1321, 1418); unmarked rows are never looked at. Not diffed though the file carries them: `serenepub.narrativeGraph` (ties, exits), `scenes`, `storyTime`, `timelineEnabled`, name, description. Primers: `plugins/providedPrimers.ts` `upgradePrimer` (216–319) diffs entries, places and leads only. A removed member comes back through `createMember` (1128–1131, called 1150–1154), which always creates a new card though `known.character` holds the old one.

**What hangs off a lorebook** (FKs from `drizzle/meta/0171_snapshot.json`; none is restrict, so no delete fails):
| Rows | "Not shipped" is | Outside references |
|---|---|---|
| `lorebook_entries` | id not in the next `mark.entries` | cascade: `anchor_entry_id` children, `scenes.history_entry_id`, amendments, annotations, vectors, redlines, relationships; set null: every `history_entry_id`, `message_annotations.ref_entry_id` |
| `lorebook_bindings` | id not in the next `mark.cast` | set null: `session_characters` / `session_personas.cast_member_id` (the seat loses its member), `messages` / `session_messages.cast_member_id`, overlay rows' `overlay_of`, `anchor_binding_id`; cascade: `character_versions`, `cast_amendments`, `cast_presences`, `cast_member_files`, `sprite_sets`, `scene_characters` |
| `attribute_values` (template layer) | key not in the next `mark.stats`, or its owner is being deleted | no FK (`owner_kind` / `owner_id`): delete explicitly |
| `narrative_relationships`, `scenes`, `cast_presences`, `lorebook_branches`, `lorebook_tags` | no mark | replace wholesale from the file |
| book columns (name, description, calendar, clock, timeline, rules) | — | set from the file |
| marked card (`characters`) | its member is gone | `session_characters.character_id` set null |
| `lore_imprints`, `lore_sources`, amendments | history | go by cascade or stay; `subject_id` is not an FK, so Back on a deleted row must no-op (nv) |

**Two cascades can reach a session's notes** (nv whether cross-book rows exist): `anchor_entry_id` deletes child entries; `scenes.history_entry_id` deletes scenes. Before the delete, null both for rows whose `lorebook_id` differs from the book (`scenes.history_entry_id` nullability nv).

**Order, one transaction:** upsert shipped rows as today → null cross-book anchors → delete values of doomed owners → delete doomed members → delete doomed entries → rewrite ties, exits and scenes → set book columns → cards → save the mark (`goneUpstream` becomes a removed count). No soft path (entries have no deleted flag; the ruling says remove). Legacy marks: a book with no `mark.cast` goes through `findLiveMember`; record the matches first, then delete the rest.

**Card reuse:** in `createMember`, when `known.character` still exists and `markedCharacter` names this plugin and slug, overwrite that card (`overwriteCharacterFromParsedData`) and bind it; add the member `key` to `ProvidedCharacterMark` (JSON, no migration) so older orphans are found by (plugin, slug, key); sweep marked cards of this plugin and slug that no member binds.

**Core starters (ap-4b).** Shipped from `SDK/core-catalog/src/registry/primers.ts` through `shippedKits()` (`lorebooks/starterKits.ts` 145); written by `writePrimerInto` (760–~950). Identity: entries, places, leads and cast carry `key` (`SDK/sdk/src/primers.ts` 68–128); relationships have none (from + to + label); exits use place key + `towards`. Plan: entries delete unmarked and gone; cast by key in a new `mark.cast` (older rows match once by name); exits, ties, lead links, sheet values deleted and rewritten by extracting those halves of `writePrimerInto`; name, description, ruleset, calendar, clock set, and cleared when the release has none. A row whose hash is unchanged but which has no `mark.cast` counts as changed once, or existing pubs never refresh. Never touched: any lorebook without its own genuine mark (`markedBook(extraJson, uuid)`): a person's own starter (AP5), copies (`bookFromKit`), session notes. nv: that no session attaches a `starter_kit` row directly.

**Hand-edit doors (ap-4c).** Closed already by `primerRowEditProblem`: `sockets/entries`, `lorebooks`, `amendments`, `redlines`, `scenes`, `narrativeGraph.*`, `entryKnowledge`, `lorebookState`, `lorebookStoryTime`, `bindingSuggestions`, `starterKits`; `state/write.ts` 2195; `ownBook.ts` 1336; `canWriteLorebook` is false for a provided lorebook. Open: `sockets/characters.ts` (update 968–1001 only keeps the mark; delete, avatar, gallery, version restore unchecked, nv per handler); `sockets/sprites.ts`, `sockets/media.ts` (no provided check); card-owner stat values (nv); a person's card action on a provided card or member (`canEditCastMember`, `mayFillSprites`, nv); the server side of the `castMemberLock` door on a provided lorebook (nv). Plan: one decider `providedCardProblem` beside `primerRowEditProblem`: *This character comes with ‹plugin›: make your own copy to change it.* Administrators are refused too.

**Decided by the lead:** a removed member's marked card that another lorebook or seat still uses is kept and loses its mark (deleted only when nothing references it); notes rows hanging on a deleted provided entry are kept with the anchor nulled; a lock or session-written annex on a provided lorebook stays (not source content).

**Tests.** Pinning today: `plugins/providedBooks.int.test.ts` 514, 1056–1107 ("gone left alone"); `providedPrimers.int.test.ts`. New: every row kind is removed; a seated session survives (seat and stamps null, nothing throws); notes rows survive; a re-created member reuses its card; a primer's cast, ties, exits, clock and name refresh; a person's starter is untouched; each card door refuses. Docs: `docs/plugins.md` 54, `docs/lorebooks.md`, `docs/characters.md`; NOMENCLATURE row ~424, §25. No migration.
