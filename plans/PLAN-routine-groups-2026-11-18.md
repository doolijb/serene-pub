## RG1 as it fits the code
Owner 2026-11-18: "Presets can declare groups, genre has a default preset." Registrations are declared on `GenreDecl.defaults.registrations` (`sdk/src/genres.ts` 1305–1308); a preset is one set of changes on those defaults (`core-catalog/src/seed/presets.ts` 28–35: "A preset that changes nothing IS the genre's defaults"). So: the genre's groups live in the genre's defaults, which the default preset presents unchanged; any preset may declare further groups, change a group's settings, and place routines. Additive.

## 1. Target shape
**(a) Declaration.** `routineGroup(cadence, { key, label?, when?, allowStacking?, caps?, run? })`; `register(group, pipeline, opts)` accepts it as a fourth trigger input. The `RegistrationDecl` keeps `trigger: { family: 'routine', cadence }` copied from the group and gains `group?: string`. `triggerKeyOf` / `registrationKeyOf` untouched: every stored routine key stays. `GenreDefaults` and `PresetRegistrationChanges` gain `groups?`; `RegistrationChange` gains `group?` and a group-change list. A routine keeps `order`, `mode`, `values`, `minAge`, `label`; inside a declared group `when`, `allowStacking`, `caps` on the routine are refused at the door. `register(cadence, pipeline, opts)` stays valid as an implicit group of one (group key = registration key). One published behaviour changes: the door's `registration caps` warning ("caps apply to routines on the system clock", `registrations.ts` ~693) goes (RG2).

**(b) Stored state.** Declared groups: new table `routine_groups`, scoped genre / preset / session like `registrations`; members carry `registrations.group_key`. One cadence counter per (session, group): `routine_groups.state` on the session-scope row; an implicit group keeps `registrations.state`. Run count per group: `sessions.routine_group_runs` (jsonb map), reset in the UPDATE `noteInteraction` already makes; the pause map in `interaction.ts` re-keyed to the group key. `sessions.routine_runs_since_interaction` stops being written (no fold needed: R21, `evaluate.ts` 234; `interaction.ts` 54–67).

**(c) Sequence vs side by side.** The queue's unit becomes a group firing (group key + members in `order`, then key). Stacking compares group keys; the drain still runs one firing at a time behind `sessionBusyForRoutines`. Sequential: members one after another through `runRoutineFiring`. Side by side: all members start at once, the drain awaits all. Write order: the SDK executor's `WriteGate` / `parallelInOrder` (`sdk/src/executor.ts` 2302–2342) already make a write-class outlet wait for everything declared before it; add `RunOptions.writeAfter` seeding the root `runLevel` gate (2652); core passes each member the earlier members' "finished or parked" promises through `runSpec` (`runtime/runTurn.ts:1116`). Limits to document: reads are not ordered (a routine that reads an earlier member's writes needs Sequential); a detached child run escapes the gate (scene summaries outlet, per INTEGRATING §1i; not traced); a member parked at review releases the gate.

**(d) Idle running.** One session setting `sessions.idle_run_minutes`: null = up to the limit (today), 0 = off, n = at most n minutes; a new layer in `capsOf`: min(system, owner's user setting, session, group). Shown in the Routines card only when an effective group is on the system clock. Governs every firing whose chain began at a system tick. An off or paused group says why in the routine log.

## Cold review corrections (2026-11-18) — these rule over the text above

1. **Keep running is OFF unless switched on (RN2), and null means off.** `sessions.idle_run_minutes`: null = off (every existing session after the upgrade, and every new one); n ≥ 1 = on, for at most n minutes. There is no 0. Switching it on stores min(the person's limit, the system limit); `capsOf` (`routines/interaction.ts` 114–131) keeps clamping. Off has its own routine-log sentence (never "no one has played for 0 minutes"). Test: an existing session's system-clock group is paused after the upgrade, with that sentence.
2. **rg-1c owns the runtime half of 2.8:** the session layer in `capsOf`; an origin mark carried on `RoutineFiringEntry` and `fromRoutine` (a chain that began at a system tick vs one that began at a send; today only `ctx.fromRoutine.depth` exists, `evaluate.ts` ~212); the Off sentence. Tests: a tick-started chain is governed at every depth; a send-started chain is not.
3. **Interleaving with the other lanes.** SDK lanes never overlap (`tc-1a`, `sp-1`, `sm-1`, `rg-1a`, `tc-1d`, `tc-1e`, `rg-1f` one at a time). `rg-1b` starts only after every turn-control lane has finished (shared `db/schema.ts`, `registrations/resolve.ts`, `boot/bootstrap.ts`); its migration takes the next free index at generation. `rg-1e` runs after `tc-1g` (the settings form files). `rg-1f` runs after `tc-1d` and `sm-1` (`core-catalog/src/genres/defaults.ts`) and re-checks which genres register scene summaries then.
4. **The boot pass carries out RN3 exactly.** For a declared group, the group takes the first member's effective values field by field (`cadence_options`, `allow_stacking`, `caps`, a `trigger_ref` swap, `when`); where the first member has no row the declaration stands, and a later member's differing values are dropped. One routine-log line per affected session says so. A member's stored `when` is moved or cleared, never left behind. The idempotence test also counts `pipeline_runs` rows (a second boot writes no second line).
5. **Reach of the setting:** the session's owner, in the Routines card, with or without Show advanced controls, and only where an effective group is on the system clock (P3: the owner changes it; to let a world keep moving unattended; without it nothing runs between sends).
6. Citation drift: `GenreDefaults` is at `sdk/src/genres.ts` 1319–1322; `runtime/runTurn.ts:1116` is inside `runSpecOnce` (693), so `writeAfter` travels on `SpecRunRequest`.
