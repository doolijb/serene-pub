## After the lane

`registrations.values` is the only store anything writes for a session's step values. The Pipelines card writes
there through `patchSessionRow` on every key in one transaction and removes any old row at the same address. The
panel resolves in the run's order: session registration value, then a left-over old row, then preset, genre and
instance, then the author's default.

## The boot pass `pipelines/boot/sessionOverrideFold.ts`

After the registrations projection and refit; one transaction per session. Per old row: a connection slot →
deleted; session gone, pipeline not run by the session's registrations, or no active version → left and counted;
every key already holds a usable value there → deleted; a value that cannot be held without changing what the
run reads (`null`, an undeclared address, a value that does not read back unchanged, a prompt whose fields the
key's own prompt does not all have) → left and counted; otherwise written with `patchSessionRow` (origin
`upgrade`) and deleted. A second boot changes nothing. One log line for what moved, one warning for what stayed.
